3. **先搬文件與已知獨立產物。** 按 mapping 逐檔搬移，保留同名不同來源，未知放 archive/unknown，保護目錄與連結跳過。檢查每個絕對目的地均位於本專案內、無大小寫衝突、無覆蓋。
4. **再處理資料／權重與路徑。** 所有讀寫方與 config 同步更新，只改路徑，不改 architecture、loss、資料切分、選模或統計。現存生成 config 保留原始證據，需要新路徑時建立新版本，不默改歷史內容。
5. **建立可追溯入口。** 更新 PROJECT_STRUCTURE／README，提供 experiment → run → config／checkpoint／metrics／figures／logs 對照。歷史日期、split、commit 不明就保留缺值；不把多來源總帳去重猜成單一實驗。
6. **驗證後才結案。** 搬前後檔數／總大小一致；對本次已 hash 的檔案比對 SHA-256，搬移未 hash 原始資料前補足驗證；確認所有模型都在 checkpoints；確保沒有遺留舊輸出路徑。路徑修正後跑必要的 import／單元檢查與不訓練的設定檢查；資料／checkpoint 配對不明者不假裝驗證成功。最後交付實際搬移清單與可逆對照。

本次驗證只涵蓋盤點及建議 mapping，不宣稱完成實際搬移或修好執行流程。沒有必要在此階段重跑實驗。
